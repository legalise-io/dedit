# Dedit code review and test quality assessment

Date: 2026-10-01. Reviewed the existing `~/Code/dedit` checkout, including its pre-existing local changes, in an isolated worktree based on commit `5a5b306`.

## Assessment

The most consequential problems were document fidelity and revision attribution: formatting could move to a different paragraph, comments could disappear or anchor to the wrong repeated text, and chained editing could classify restored deletions as new insertions. Those paths deserve regression protection because a plausible-looking editor can still export the wrong legal document.

Confirmed defects were exercised with failing tests before repair. The completed suite has **193 passing tests**: 88 Python, 99 frontend and 6 collaboration. It has no expected failures or skipped bug tests. Product and test TypeScript checks pass, and both the demo and library builds pass. Findings below are fixed in source; dependency advisories are discussed separately because this review did not demonstrate application exploitation.

## Original test quality

There were nine local, untracked tests: seven DOCX tab tests and two extension-factory tests. The tab assertions usefully checked OOXML and tracked formatting; the factory checks protected schema construction and collaboration/history configuration. However, they covered a narrow part of behavior, were absent from the committed checkout, and the tab tests depended on an ignored private DOCX fixture. There was no established root test command, coverage gate or CI test workflow.

The new suite keeps these assertions and replaces the private file with generated fixtures. It adds real document conversions and editor transactions, failure paths, React lifecycle tests and an actual collaboration roundtrip. Most assertions check externally meaningful state rather than implementation snapshots. Provider and AI doubles are limited to lifecycle/network boundaries; editing and conversion logic executes normally.

## Confirmed findings and fixes

Severity describes the original user impact. Test names below can be run with the commands in [TESTING.md](../TESTING.md).

### High: document fidelity and editing history

1. **Paragraph properties followed traversal indices after insertion.** Import an indented paragraph, insert a new paragraph before it, then export: the indentation moved to the new paragraph. Converter-generated paragraph/heading IDs now key preserved `pPr`; exporter reads the stable key with a legacy index fallback. Files: `docx2tiptap/src/docx2tiptap/{tiptap_converter,docx_exporter}.py`. Regression: `test_inserting_paragraph_does_not_move_original_indentation` in `tests/test_regressions.py`. Newly imported documents get the protection; legacy index-only payloads remain subject to their original structural limitations.

2. **Comments disappeared on imported formatted text.** Export collected a `None` comment anchor when raw run properties were present. Raw-run creation now returns a real python-docx `Run`, which is registered for comments. File: `docx_exporter.py`. Regression: `test_comments_on_imported_formatted_text_survive_export`.

3. **Comments disappeared on tracked text.** Insertion/deletion paths never collected comment anchors. Both now return their run and use the shared anchor collection. File: `docx_exporter.py`. Regression: `test_comments_on_tracked_text_survive_export`.

4. **Repeated text lost comment boundary identity.** Importing two identical runs with only the first commented could merge them or associate the wrong occurrence. Revision traversal now carries active comment IDs per segment; merging respects those IDs and the parser consumes them directly. Files: `revisions_parser.py`, `docx_parser.py`. Regression: `test_repeated_text_has_comment_on_correct_occurrence`. Overlapping ranges also have direct parser coverage.

5. **Preserved raw formatting overrode the editor's current marks.** Removing bold in TipTap left the original raw `w:b` effective on export. Raw run properties now reconcile bold/italic against current marks while preserving other properties. File: `docx_exporter.py`. Regression: `test_removing_bold_in_editor_removes_bold_in_word`.

6. **Blank paragraphs were dropped on import.** A before/blank/after document became before/after. Empty paragraphs now survive parsing. File: `docx_parser.py`. Regression: `test_blank_paragraphs_are_preserved`.

7. **Headings inside tables lost revision wrappers.** The heading path bypassed revision-aware text export. It now uses the same text handler as ordinary paragraphs. File: `docx_exporter.py`. Regression: `test_heading_revision_inside_table_is_preserved`.

8. **Remote Yjs edits were attributed again to the receiving author.** A remote insertion by Bob received Alice's insertion mark when local tracking was enabled. The tracking plugin now bypasses Yjs-origin changes, including Yjs undo. File: `frontend/src/extensions/track-changes/trackChangesPlugin.ts`. Regression: `remote Yjs transactions retain remote attribution` in `frontend/tests/regressions.test.ts`.

9. **Multi-block paste left later text untracked.** Text-length-based offsets did not include block boundaries. Inserted slice descendants now use their actual offsets and map through later steps. File: `collectChanges.ts`. Regression: `multiple inserted blocks all receive insertion marks`.

10. **Chained replacements used the wrong document and position mappings.** Multiple insert/delete steps could restore transient text, mark the wrong original characters, or produce the wrong final clean text. Collection now examines the document before each step, inversely maps only prior steps to distinguish original from transient characters, and maps surviving insertions through subsequent steps. File: `collectChanges.ts`. Regressions: `multi-step editing uses the document before each step` and four parameterized `chained replacements preserve original deletions and final clean text` cases.

11. **Restored deletion text was included in an insertion range at its endpoint.** A replacement could turn original deleted characters into insertions. Insertion endpoint mapping now uses the boundary association that excludes restored adjacent text. File: `applyChanges.ts`. The chained replacement regressions above assert final clean text and revision separation; ordinary replacement and deletion-fragment tests cover adjacent cases.

12. **Splitting a paragraph duplicated its stable ID.** This made paragraph-targeted AI operations ambiguous. Split attributes stop retaining IDs, and an appended transaction repairs missing or duplicate paragraph/heading IDs synchronously. File: `frontend/src/extensions/ParagraphWithId.ts`. Regression: `split paragraph assigns unique stable IDs`.

13. **AI edits parsed generated plain text as HTML; diff offsets also lost whitespace.** An edit to `hello <b>literal</b>` produced parsed markup or an invalid old offset. Edits now insert explicit JSON text nodes, and diffing uses `diffWordsWithSpace`. Files: `frontend/src/lib/ai/{applyEdits,diffUtils}.ts`. Regression: `AI plain text containing markup is inserted literally`; diff tests check whitespace and old offsets. This is a text-integrity finding, not a demonstrated XSS exploit.

14. **Collaboration filenames aliased distinct document names.** Sanitization mapped `a/b`, `a_b`, punctuation and Unicode names to overlapping paths, allowing one document to overwrite another. Persistence now hashes the full name, writes via a temporary file plus rename, and reads legacy names only when already safe. File: `collab-server/persistence.js`, used by `server.js`. Regression: `names with punctuation and unicode never alias`; binary roundtrip, failed-write and real server-restart tests also pass. Existing ambiguous legacy filenames require manual migration because their original names cannot be recovered reliably.

### Medium: API, hooks and interaction

15. **GET of an uploaded document returned binary ZIP bytes through JSON encoding.** FastAPI attempted to decode the original DOCX and returned 500. `backend/main.py` now excludes `original_bytes` from the public response while retaining it for template export. Regression: `test_uploaded_document_can_be_retrieved`.

16. **Explicit disabled Word bold/italic values were treated as enabled.** Parser checked element presence rather than `w:val`. It now honors `0`, `false` and `off`. File: `revisions_parser.py`. Regression: `test_explicitly_disabled_bold_is_not_imported_as_bold`.

17. **Malformed preserved XML raised during export instead of falling back.** Base64 decode errors escaped the helper. `utils.py` now returns `None` for invalid base64/XML and uses an XML parser with network/entity resolution disabled. Regression: `test_bad_raw_xml_returns_none` in `tests/test_conversion.py`. Raw-property consumers retain their existing fallback behavior.

18. **The supported minimum python-docx version silently lost comments.** The declared `>=1.1.0` permits a version without `Document.add_comment`. An isolated run with 1.1.0 failed `test_comments_on_plain_text_roundtrip`, printing the missing-method error and producing zero comments. The package now requires `>=1.2.0`; the same behavior test passes with 1.2.0. File: `docx2tiptap/pyproject.toml`.

19. **Paragraph acceptance used a selector absent from the rendered DOM.** The helper looked for `data-id`; paragraphs/headings expose `data-paragraph-id`/`data-block-id`. File: `frontend/src/lib/ai/applyEdits.ts`. Test coverage in `frontend/tests/utilities.test.ts` checks paragraph acceptance and navigation behavior.

20. **Document hook ignored readOnly updates and recreated the editor for equivalent inline content.** A prop update left the editor writable; a freshly allocated but identical content object could trigger repeated editor creation. An effect updates editability and a serialized content key stabilizes the dependency. File: `useDocumentEditor.ts`. Tests: `document hook creates editor, changes content, toggles readOnly and destroys on unmount`, `equivalent inline initial content does not recreate the editor on rerender`.

21. **Collaboration document switches retained the previous seeding flag and leaked the old Y.Doc.** Seeding is now scoped to the current document; cleanup disposes the old document, with deferred disposal cancelled for an immediate StrictMode effect replay. File: `useCollaboration.ts`. Regression: `new document can seed after the previous document was seeded`; provider destruction, presence and existing-content tests also pass.

22. **Delayed change navigation accessed a destroyed editor.** The delayed callback now checks destruction and position bounds before geometry access. File: `useChangeNavigation.ts`. Regression: `delayed change navigation does not access a destroyed editor`. Removing the guard reproduced `Cannot read properties of null (reading domFromPos)`; restoring it made the test pass. Browser layout itself is not established by these tests.

23. **AI editor registration read a stale ref and retained listeners on old editors.** Registration now updates the ref immediately; an effect installs and cleans up listeners. File: `frontend/src/context/AIEditorContext.tsx`. Regression coverage in `frontend/tests/ai.test.tsx` checks selection context and listener cleanup when switching editors.

24. **Context-item batch deduplication allowed duplicate IDs within a batch.** Filtering now records accepted IDs as it processes the batch. File: `useContextItems.ts`. The AI context tests assert that a repeated batch ID is added only once.

25. **Backspace could not clear a selected prompt mode.** The injected nonbreaking-space spacer prevented the empty-text condition. File: `PromptInput.tsx`; checking trimmed text restores the command. The prompt interaction test in `frontend/tests/components.test.tsx` covers this path.

26. **Tab exceeded Word's maximum numbering level.** A level-eight paragraph became level nine, which cannot be represented by the supported Word list levels. `StyleNumbering.ts` now consumes Tab at level eight. Regression: `numbering cannot exceed Word's maximum level eight` in `frontend/tests/numbering.test.ts`. The test was observed failing with actual level nine before the fix.

27. **CommonJS package entry failed to load.** During release preparation, loading `dist/index.cjs` reproduced `Table.extend is not a function` while ESM loaded successfully. The library build now uses automatic external dependency interoperability. Regression: `scripts/check_frontend_package.mjs` loads each module format in its own Node process and checks the exported extension factory; CI runs it after the build.

## Remaining risks and test limitations

- **Dependency advisories:** The captured frontend `npm audit` reported 47 advisories (2 critical, 13 high, 30 moderate, 2 low), including transitive packages; this is not 47 reproduced application defects. TipTap 2 inherits the executable-attributes/prototype-pollution advisory `GHSA-cp6q-959q-f8rh`; its reported fix requires TipTap 3. Vitest 2 has dev-server advisories, including `GHSA-5xrq-8626-4rwp`; this suite invokes the CLI runner without opening its UI server. Vite and declaration tooling also need upgrades. Plan a compatible dependency migration and retest; automatically forcing major upgrades would change the editor API consumed by fredit. `diff` and `uuid` advisories concern APIs other than the word-diff and v4 UUID paths inspected here. No exploitation claims are made.
- **Word interoperability:** Generated fixtures cover ordinary formatting, tracked text, comments, numbering, tables and preserved XML. They do not establish exhaustive Word fidelity for complex section layout, embedded objects, all numbering definitions, comment replies or every possible cross-paragraph revision. Reopened DOCX and XML checks cannot replace a compatibility corpus validated in Word.
- **Browser behavior:** jsdom tests exercise real editor state and component events, with geometry stubs. Real selection/IME behavior, accessibility, layout, drag/drop and visual rendering still need browser tests. The demo App is included in coverage but largely unexercised directly.
- **Concurrency:** Real WebSocket synchronization and persisted restart are covered. Hook lifecycle uses a provider double; long concurrent sessions, network partitions and simultaneous complex structural edits need additional stress tests.
- **Operational scope:** The backend and collaboration listener are development components. These tests do not assess production authentication, authorization, quotas or deployment durability. The API's corrupt-upload response remains its existing 500 contract, with a test that verifies it does not store a document.
- **Build warnings:** Declaration tooling uses an older bundled compiler than the installed TypeScript version, and the demo bundle exceeds Vite's size-warning threshold. Both builds complete successfully; these warnings are not evidence of broken output.

## Relevance to fredit and delivery

Fredit's `scripts/vendor-dedit.sh` builds a local dedit editor tarball and converter wheel, and checks for a separate fredit track-changes patch. Shared conversion, schema, paragraph identity and transaction fixes are directly relevant to those dependencies. Dedit-only demo API/hook/server findings matter when those exported features or services are used.

Changes were transferred into the existing `~/Code/dedit` checkout while preserving its prior local work. No commit or publish was performed. Fredit's vendor artifacts were not rebuilt; its current installed artifacts therefore do not automatically contain these fixes. A subsequent vendor refresh must reconcile its existing track-changes patch with the revised dedit transaction code before rebuilding.
